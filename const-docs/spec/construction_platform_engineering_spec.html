SECTION 01

Product Objective & Core Scope

Mandatory MVP

Build a branded, multi-company construction management platform unifying estimating, cost control, project scheduling, quality/defect tracking, BIM issue coordination, and field reporting into a single experience. Customers must interact exclusively with your brand's frontend, domain, and API.

Estimating & BOQ

Hierarchical bill of quantities with high-precision decimal calculations, unit rate libraries, and change orders.

EVM & Cost Control

Automated Planned Value (PV), Earned Value (EV), Actual Cost (AC), and real-time SPI/CPI trend metrics.

Project Management & Gantt

Interactive Gantt schedules, baseline tracking, activity dependencies, and progress reporting.

Issues & BIM/BCF

Defects, RFIs, change requests, and snags integrated with OpenProject BIM and Open BIM BCF standards.

Field Operations & PWA

Site diaries, geolocated photo uploads, checklists, digital signatures, and offline synchronization queues.

Tenancy & Localization

Strict multi-company tenant isolation, English/German (DE/EN) language packs, and EUR/PKR currency formats.

SECTION 04

Upstream Engine Provisioning Specifications

Pinned Versions

4.1. cost-core (OpenConstructionERP) DNS: cost-core.internal:8069

  • Deploy with a pinned release tag or sha256 digest. Never use dynamic latest tags.
  • Run against an isolated PostgreSQL instance (cost_core_db). Do not share tables with middleware.
  • Disable all public Ingress controllers. Ingress is restricted via Kubernetes NetworkPolicy strictly to pods with label app: const-middleware.
  • Provision a dedicated machine service account: svc_middleware_cost with scoped API tokens stored in HashiCorp Vault / Sealed Secrets.
  • Verify full programmatic CRUD for Projects, Work Breakdown Structure (WBS), Bill of Quantities line items, and cost journal entries.

4.2. pm-core (OpenProject Community/BIM Edition) DNS: pm-core.internal:8080

  • Deploy pinned release with standalone database (pm_core_db).
  • Configure SECRET_KEY_BASE securely via external secrets manager.
  • Enable OpenProject API v3 and configure OAuth2 machine credentials or API keys for the middleware service account.
  • Activate the BCF module (Building Collaboration Format) for BIM issue management.
  • Seed standard Work Package types: [ "Defect", "RFI", "Change Order", "Snag", "Safety", "Design", "Activity" ].
  • Seed standard statuses: [ "Draft", "Submitted", "Under Review", "Approved", "Rejected", "Closed" ].
  • Configure custom fields: cfield_bcf_guid, cfield_cost_impact, cfield_time_impact.

SECTION 08

Integration Adapters & Circuit Breaker Architecture

Port-Adapter Pattern

Upstream APIs are isolated behind strongly typed TypeScript port interfaces. Under no circumstances should controllers call upstream REST paths directly or pass raw engine errors to users. 

// Location: src/integrations/ports/cost-core.port.ts
export interface CostCorePort {
  createProject(input: {
    localProjectId: string;
    name: string;
    currency: 'EUR' | 'PKR';
    idempotencyKey: string;
  }): Promise<{ externalId: string }>;

  createBoqItem(projectId: string, input: {
    code: string;
    description: string;
    quantity: string;
    unitPrice: string;
    currency: string;
  }): Promise<{ externalId: string }>;

  getProjectActualCosts(externalProjectId: string): Promise<{ actualCost: string }>;
}

// Location: src/integrations/ports/pm-core.port.ts
export interface PmCorePort {
  createProject(localProjectId: string, name: string): Promise<{ externalId: string }>;
  createWorkPackage(input: {
    localIssueId: string;
    externalProjectId: string;
    title: string;
    type: string;
    priority: string;
    bcfTopic?: any;
    idempotencyKey: string;
  }): Promise<{ externalId: string; bcfGuid?: string }>;
  
  getProjectProgress(externalProjectId: string): Promise>;
}

Circuit Breaker & Outbox Guarantees

  • Trip Threshold: 5 consecutive upstream 5xx errors within 60 seconds trips the circuit breaker to OPEN.
  • Fallback Behavior: All mutating requests persist locally with sync_status: 'pending', returning a 202 Accepted or 201 Created along with a synchronized status badge.
  • Retry Schedule: BullMQ queue processes retries at exponential backoff intervals (5s, 30s, 2m, 10m, 30m) with strict idempotency keys.

SECTION 10

Critical Domain Workflows & Mathematical Pipelines

Business Logic

10.1. Project Provisioning Workflow

  1. Client calls POST /v1/projects with required Idempotency-Key header.
  2. Middleware verifies company membership, active tenancy status, and currency (EUR or PKR).
  3. Insert local projects record with status: 'provisioning'.
  4. Enqueue job to BullMQ project-provisioning queue.
  5. Worker creates cost-center in cost-core → records internal mapping erp_project_id.
  6. Worker creates project in pm-core → records internal mapping pm_project_id.
  7. Seed default work-package categories and custom BCF fields.
  8. Transition local project status to active, write an audit event, and emit completion WebSocket event.

10.2. BOQ Decimal Math & Recalculation

All arithmetic uses Decimal.js with strict ROUND_HALF_UP precision:

total_price = quantity.times(unit_price).toDecimalPlaces(2, Decimal.ROUND_HALF_UP);
// Parent section total = sum of child items total_price

Every write generates an outbox entry. If cost-core is unreachable, local modifications remain active while the row displays a pending sync indicator.

10.3. EVM Metrics & Division-by-Zero Protection

A nightly cron aggregates progress from pm-core and financial actuals from cost-core:

Schedule Performance Index (SPI)

SPI = EV / PV

*If PV == 0, store NULL (do not store Infinity or NaN)

Cost Performance Index (CPI)

CPI = EV / AC

*If AC == 0, store NULL (do not store Infinity or NaN)

Snapshots are saved to evm_snapshots as an immutable historical record. An automated alert triggers if SPI or CPI falls below 0.85.

10.4. Object Storage & Secure Presigned I/O

Binary files never pass directly through the middleware Node.js runtime process:

  1. Client requests presigned URL via POST /documents/presign.
  2. Middleware generates storage key: companies/{company_id}/projects/{project_id}/documents/{document_id}/{safe_filename}.
  3. Client streams binary directly to S3 / MinIO via PUT.
  4. Client invokes POST /documents/complete with SHA-256 hash and exact byte size.
  5. Asynchronous worker verifies S3 object headers and queues ClamAV antivirus check before marking the file as available.

Observability, Telemetry & Scrubbing Rules

Zero Leakage

Every HTTP transaction is assigned an immutable request_id header passed through downstream queue jobs and logs.

Core Metrics Monitored
  • API response latency and 5xx error distribution
  • Project provisioning success and failure rates
  • BullMQ queue depth, retry rates, and dead-letter jobs
  • EVM nightly aggregation run execution time
  • S3 upload failures and ClamAV quarantine triggers
Zero-Leakage Scrubbing Rules

The logging pipeline must redact matching keys before writing to disk or OpenTelemetry collectors:

password, password_hash, token, authorization, cookie, amqp://*, postgres://*, *.internal
SECTION 14

Comprehensive Verification Test Matrix

Quality Assurance
1. Multi-Tenant Isolation Test

A user authenticated in Company A calls GET /v1/projects/:id_from_company_b. Expected outcome: 404 Not Found with zero tenant leakage.

2. Security & Information Leakage Audit

Force an error in upstream services. The customer-facing response must contain only a generic message, our internal error code, and a request ID. No upstream product names, SQL schemas, or stack traces may appear.

3. Financial Decimal Precision Test

Create a BOQ item with quantity = 0.3333 and unit_price = 10.00. Expected result: total_price = 3.33. IEEE-754 floating-point drift is not allowed.

4. Upstream Outage Recovery Simulation

Stop the pm-core container and submit an issue via the API. The record must be created locally with status pending_sync. Once pm-core is restarted, background workers must clear the queue and mark the issue as synced without duplicate records.
